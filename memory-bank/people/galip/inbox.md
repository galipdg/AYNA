- 2026-10-25 · from hasan · #9 · Four measured facts about Qt/UIA from the trial app that affect `recognition/` and `heal/`, all in `memory-bank/learnings.md` (PR #116, dump in `eval/apps/trial/uia_dump.py`): (1) Qt builds the **AutomationId as a dotted path** over the object chain — `QApplication.loginWindow.usernameInput`, not `usernameInput` — so descriptors must store the full id and renaming an ancestor invalidates every descendant (a fragility source for RQ1 and for D1 #21); (2) `accessibleName` is mapped onto the UIA **Name** and *replaces* it, hiding a window's title and a label's text, so a checkpoint cannot read what it is meant to verify — do not advise "accessibleName everywhere" in the testability guideline; (3) Qt exposes the Python/C++ **class name as the UIA ClassName** (`LoginWindow`), which is the most stable handle for finding a window; (4) a window frame contributes id-less Windows controls (TitleBar, System menu, Minimize/Maximize/Close), so any "every button has an id" rule must be scoped to the app's own `Q*` widgets.
