# Agent JSON-RPC v0: handshake token, env-var token, ready line

- Date: 2026-10-27
- Status: Accepted (Ömerfaruk and Hasan approved the #16 PR, 2026-10-29)
- Deciders: Galip (proposal), Ömerfaruk, Hasan
- Issue: #16

## Context
The Electron client drives the agent through JSON-RPC over a localhost WebSocket (`architecture.md`). Any process on the machine, and any web page in a browser, can reach a port on 127.0.0.1, and the agent can click and type in every app. #16 asks for a 127.0.0.1-only server, a token and port given by Electron, and the methods `ping`, `listWindows` and `snapshot`. The contract (`docs/agent-rpc.md`) freezes at G1 and binds the client (omer) and the recognition backend (hasan).

## Decision
- **Token in the opening handshake** as `Authorization: Bearer <token>`, compared in constant time. Anything else gets HTTP 401 before a socket opens. Browsers cannot set this header on a WebSocket, so a web page cannot open a session. The client therefore connects from its main process with a client that sets headers.
- **Token through `AYNA_AGENT_TOKEN`**, not a command-line flag, because other processes can read command lines. The agent removes the variable from its environment, so the apps it starts do not inherit it. At least 16 characters; the client makes a fresh random one per session.
- **`--port 0` by default, and one JSON ready line on stdout** (`{"event": "listening", "port": n}`). The OS picks a free port, so there is no race between Electron choosing a port and the agent binding it. Electron may still pass a fixed port.
- **The agent exits when its stdin closes** (review of #135, omer). The client holds a stdin pipe it never writes to, and the OS closes it when the client quits or crashes, so an agent with UIA access never outlives its client. A terminal on stdin is not watched.
- **JSON-RPC 2.0, strict and small:** one request per text frame, no batches, params by name. Each request runs in its own task and **replies come in any order, matched by `id`** (review of #135, hasan): `ping` answers during a long snapshot, and a future "stop run" request will not wait behind the run. App error codes are `-32000` (window not found), `-32001` (UI Automation unavailable) and `-32002` (snapshot timeout).
- **`snapshot` takes an optional `timeoutMs` budget** and refuses unknown params. In the #6 dumps one walk took 278.5 s for 106 elements (KeePass 2, WinForms). Its cause is still open (#161), so the agent needs a bound either way: the backend stops at the budget and answers `-32002`. There is no partial document in v0.1. More limits (depth, element count) can come with #12 as a minor bump.
- **UI Automation behind a `Desktop` protocol** (`list_windows()`, `snapshot(handle, timeout_ms)`, optional `setup()` / `close()`) that `recognition/` implements. All calls run on one dedicated worker thread in arrival order, so COM is initialised once (in `setup()`) and UIA walks never overlap. Windows are addressed by their native handle (HWND).
- **Coordinates are physical pixels** in virtual-screen coordinates: the agent process is per-monitor DPI aware (v2). Display scaling of 125 % is the default on the team's Windows machine, and the Spy overlay and playback depend on these numbers.
- **Library:** `websockets` 17 (asyncio API), a runtime dependency of `agent/`.

## Options considered
- Token as a query parameter: works from a browser-style client, but ends up in logs. It would also let any page that learns the token connect.
- Replies in request order (the first draft): simpler, but a `ping` or a future cancel waits behind a long call. Switching to unordered replies after the G1 freeze would break clients that rely on order; the other way round breaks nobody.
- A partial snapshot when the budget runs out: useful for browsing in the Spy, but it would be unsafe to build repository objects from. It can come later as an opt-in param.
- Token in the first JSON-RPC message (`hello`): every method must then check session state, and an unauthenticated socket stays open meanwhile.
- Electron picks the port and passes it: simpler to read, but racy. Still supported with `--port n`.
- Named pipes instead of TCP: no port for other users to reach, but needs Windows-specific code in both Node and Python and is awkward to test on macOS.

## Consequences
- The client (omer) spawns the agent with a stdin pipe, reads the ready line, connects from the main process with the header, and matches replies by `id`. On quit it closes stdin, then kills the tree of the PID it spawned after a grace period. The WebSocket client library is omer's choice, for example `ws`.
- The recognition backend (hasan) raises `WindowNotFound` / `UiaUnavailable` / `SnapshotTimeout` from `ayna_agent.rpc`. It enforces the snapshot budget itself, because the server cannot cancel a running UIA call. It returns window objects with the fields in `docs/agent-rpc.md` and snapshots per `schemas/snapshot.schema.json` (#12). With the backend it sets per-monitor-v2 DPI awareness at startup.
- New methods (playback, Spy hit-test, healing) are additions: `rpcVersion` minor bump plus a section in `docs/agent-rpc.md`.
